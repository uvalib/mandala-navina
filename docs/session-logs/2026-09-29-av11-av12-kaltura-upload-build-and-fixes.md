## Claude — 2026-09-29 14:15

**AV11** is the "Kaltura Session (KS) minting service" — a small server-side piece in `mandala_kaltura` that hands the browser a Kaltura Session token so it can upload media directly to Kaltura, without ever exposing the real Kaltura admin credentials to the client.

**Why "minting"?** A Kaltura Session (KS) is like a signed, time-boxed access token — Kaltura's API requires one on every call, including uploads. To create one you need the partner's admin secret (`kaltura_admin_secret`). That secret must never reach the browser, so instead:

1. The server (Drupal, via the official `kaltura/api-client-library` PHP SDK) holds the real secret — delivered at deploy time via the project's existing ccrypt-encrypted env-var pattern (`container_0.env.secret`), never committed to `config/sync`.
2. When a user is about to upload a file, the server calls Kaltura's session API using that secret to generate ("mint") a **new, short-lived KS** — narrowly scoped just for uploading, not full admin access.
3. That short-TTL KS (not the secret itself) is handed to the browser, which then uses it directly against Kaltura's chunked upload endpoints (`uploadToken.add` → `uploadToken.upload` → `media.add`), bypassing Drupal/PHP/the ALB entirely for the actual file bytes.

This is the security-critical piece AV12 (the browser upload widget) depends on — AV12 can't be built safely until AV11 exists, since AV12 is the thing that consumes the minted KS. Both were deferred on 2026-09-15 pending your availability, and per the sprint doc they're not technically blocked — just paused on sequencing/capacity.
